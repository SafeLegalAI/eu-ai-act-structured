# Common rules for every SafeLegalAI collection agent (read before the dataset brief)

You are collecting one slice of an open dataset published by **SafeLegalAI** (safelegalai.com, Cognesio LLP) under CC BY 4.0, mirrored to Hugging Face, with one indexable page per row on the site. Everything you write will be read by lawyers, journalists and answer engines, and may be checked by the people it names.

## The rule that governs everything
**We record what the primary source says; we do not infer, judge, rank or advise.** Every coded field is your good-faith reading of the primary text; when the text does not address a point use the schema's `not-addressed` / `unknown` / null value. If you could not retrieve the primary text, say so in `verification` and `notes` — never fill a field from a secondary description as if you had read the document. Never write the words *independent*, *unbiased*, *best*, *leading*, *top*, or any ranking. Describe allegations as allegations ("the complaint alleges"), findings as the court's ("the court found"), vendor claims as the vendor's ("the vendor states"). Product LegalAI Space (an affiliated product) is never included, counted or compared.

## Legal rules for sources (non-negotiable)
- **Primary sources only** for `source_url`: the court's, regulator's, legislature's, agency's or vendor's own site, or an official gazette/API (govinfo.gov, federalregister.gov, eur-lex, legislation.gov.uk, gov.uk, uscourts.gov, `*.uscourts.gov`, state judiciary sites, LegiScan/Open States/Congress.gov APIs). US federal works and US judicial opinions are public domain and may be quoted at length; state edicts (statutes, court rules, orders) likewise; EU Official Journal texts are reusable with attribution; UK OGL material with attribution. **Everything else is copyrighted expression: quote at most 25 words per fact**, in quotation marks, with the URL.
- **Never use as `source_url`, and never fetch programmatically**: Westlaw, Lexis, Law360, Justia, Google Scholar, CanLII, AustLII, BAILII, Indian Kanoon, Crunchbase, PitchBook, LinkedIn, PR Newswire, Business Wire, the AI Incident Database, law-firm client alerts, blogs, or any tracker/compilation. You may *read* trackers (Charlotin's CC0 databases, GWU DAIL, NCSL, rlegaltech, TVPi, Perlman, FLI…) and news to learn that something exists — record them in `lead_source` — then find and read the primary document. Find Case Law (UK) judgments may be read by a human one at a time and linked, never bulk-fetched or machine-processed.
- **CourtListener / Free Law Project**: their HTML is robots-disallowed and their membership API excludes for-profit tooling (a partnership request is pending). You may use the anonymous search API sparingly for *discovery only* (≤ 5 requests/minute, ≤ 100 requests in your whole task, `type=o` or `type=r`), and must fetch the actual document from the court's own `download_url` or a court/govinfo site. If the only copy is on `storage.courtlistener.com`, you may fetch that single PDF (it is a public-domain court document) at ≤ 1 request / 5 s, and must record `courtlistener_url`. Never crawl courtlistener.com pages.
- **Politeness**: `curl -sL --max-time 60 -A "SafeLegalAI-Bot/1.0 (+https://safelegalai.com/datasets; hello@safelegalai.com)"`; at most one request per second per host (one per 5 s for small sites); check `/robots.txt` before fetching a host you have not fetched before and obey it (if a path is disallowed, do not fetch it — record `verification: "link-only"`); no logins, accounts, forms or paywall workarounds; if a host returns 403/429, stop fetching that host, try `https://web.archive.org/web/2026/<url>` once, and otherwise record `link-only`. PDFs: `pdftotext -layout file.pdf -`; skip files over 25 MB.
- **Archive**: for every row try once `curl -sI --max-time 30 "https://web.archive.org/save/<source_url>"` and record the returned `location`/`content-location` as `archive_url` (`https://web.archive.org/web/<ts>/<url>`); if it fails, null — do not retry.
- **People**: name individuals only as they appear in the caption or official document; never add personal details; use the court's own anonymisation (initials) where the court used it; flag sensitive matters (children, sexual offences, mental health) with the schema's `sensitive` field if it has one and keep the description to the ruling. Never host or link to alleged deepfake media itself.
- **Dates** ISO `YYYY-MM-DD` (or `YYYY-MM` if only the month is known, with a `notes` explanation); `fetched_at` is the ISO timestamp of your read.

## Writing style for `summary` fields
40–60 words unless the schema says otherwise, present tense, self-contained, names the body, the date, who is bound or affected and what the document does. Plain, descriptive, no adjectives of judgement. A reader who sees only the summary must not be misled about the outcome.

## Output discipline
Append one JSON object per line to the file named in your task (`work/agents/<table>-<slice>.jsonl`), conforming exactly to the JSON Schema in `schema/<table>.schema.json` — read the schema first (`cat schema/<table>.schema.json`). Validate as you go: `python3 -c "import json;[json.loads(l) for l in open('work/agents/<file>')]"` and, if `jsonschema` is available in `.venv`, `.venv/bin/python -c "import json,jsonschema;s=json.load(open('schema/<table>.schema.json'));[jsonschema.validate(json.loads(l),s) for l in open('work/agents/<file>')]"`. Never write duplicate rows for the same document; if you find a later version, write one row and describe the earlier one in `notes`.

## When you are done
Reply with a short report only (the data is in the file): rows written; counts by `verification`; sources checked with zero findings (so we know they were covered); anything needing a human (ambiguity, conflicts, sensitive rows, hosts that blocked you). Do not paste rows into the reply.
